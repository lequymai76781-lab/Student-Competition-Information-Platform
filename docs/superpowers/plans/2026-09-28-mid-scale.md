# 中规模真实数据扩展实施计划

**Goal:** 在独立候选库扩大到约 80 个赛事、30 所高校，验证恢复、幂等、映射、审核队列和性能。

**Architecture:** 复用 CrawlerJob.metadata 检查点和 ReviewQueue 字段候选。每条来源独立事务，候选与检查点一起提交；失败不污染其他来源。学校关系保留为结构化待审材料，不把通知转换为认定或赛事本体字段。正式库不写入，不新增表。

**Tech Stack:** Python / SQLAlchemy / FastAPI / SQLite / Next.js / Playwright。

**Spec:** 用户附件 ca2b1a54-e09f-4e0d-85ed-7c14cff87554/已粘贴的文本.txt。

## 约束与执行

- 用户明确预授权本轮正常本地开发，连续执行，不追加设计批准环节。
- 复用当前工作区，保留所有前阶段未提交改动；不自动 commit、push、merge 或部署。
- 正式库 SHA256 起止一致；旧 107 条候选库也保持原样，新库复制独立试点公开数据。
- 来源质量 A–E 只用于提示；新资料全部未核验待审。
- 来源无法访问、年份不明、身份含糊都显式记录，不填造事实。

## Review Focus

- 崩溃发生在候选创建和检查点之间：事务回滚或恢复幂等，不能半成功。
- 同 URL 内容变化、只更新抓取时间、不同来源相同零字段：分别新增版本、去重、保留各自来源。
- 部门名与相似学校名：只认完整学校边界，歧义隔离，不创建重复学校。
- 政策未列明确赛事、未明届次、校内截止：不能推断正式认定、赛事年份或全国截止。
- 中规模分页不能对所有记录反复构建完整字段详情；动态冲突筛选须保持准确。
