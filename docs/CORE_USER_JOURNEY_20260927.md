- 首页/大厅仅列985且只取前100所；首页、详情写死2026年。
- `frontend/src/lib/api.ts` 把服务失败变为空数据/404。
- 详情概览优先取作品截止却可能标成报名截止；详情缺少学校选择控件；截止依据枚举与后端不一致。
- 纠错表单缺少提交中和失败反馈；纠错审核默认选择最新年份而非明确的目标届次。
- `review_queue` 有204条pending，尚无用户补充。正式库有50条历史已批准纠错；本轮不清理。

## E. 技术债

- README、CURRENT_TASK与代码不一致，部分恢复文档乱码；旧/新政策关系接口并存。
- 首页个性化、公共列表和数据工程统计有不同状态口径，需逐步统一。
- 当前小规模目录采用应用层精确状态筛选；扩量后需基于同一规则做数据库查询优化。

## F. 本轮设计和顺序

按用户授权连续修复现有链路，无生产迁移、无正式数据写入、无抓取扩量、无部署变更。复用当前干净工作目录；最终留可审查diff，不自动提交或发布。

1. 日期状态：只读按请求时间计算；终止/已结束状态不重新开放；仅已核验届次进入可行动列表。按学校有效截止过滤，选择同一届次再排序/分页。统一列表、详情和首页计数。
2. 用户界面：全部学校选择、保留筛选上下文、页码、正确日期标签、7天内截止提醒、404与服务失败区分、加载状态、手机排版。
3. 信息补充：复用现有审核结构；用户补充只进入待审，不伪造正式事实。纠错支持明确届次，截止审批保留来源、修订和审计。其他类型仍需人工整理，不冒充已入库。
4. 验证：先用内存fixture回归复现，再修复；全量pytest、lint/typecheck/build；独立临时副本启动API和前端进行桌面/手机浏览器验收；前后正式库SHA256一致。

## 验收重点

- 过期状态、未来报名开始、官方截止与通用截止不同、未核验/取消、跨年/多届次、校内更早截止。
- 排序后分页；筛选结果与卡片/详情当前届次一致。
- API失败不可显示为空结果；真正404才显示不存在。
- 新赛事无正式ID也能提交补充；提交失败保留文本；登录后返回原位置。
- 管理员不得将未绑定届次/无来源的截止更改写入正式事实。
