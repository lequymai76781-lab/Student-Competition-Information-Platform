# BaoyanNews 参考转化：信息架构落地方案

日期：2026-09-13  
范围：只定义信息组织、数据门槛和增量落地顺序，不设计视觉稿，不修改首页。

## 1. 转化原则

借鉴的不是 BaoyanNews 的页面外观，而是它把“发现机会—确认截止—查看官方原文—采取行动”压缩成一条短路径。本项目应把竞赛、学术会议和高校证据放进同一信息入口，但必须维持事实边界：

- 全国赛事存在、级别、主办方：赛事官网、主办方、国家/部级正式来源。
- 高校认可：学校正式目录或政策文件。
- 高校通知：学校/学院发布的报名、选拔、提交等通知。
- 高校参与：获奖、结果或活动报道；不得提升为“学校认可”。
- 搜索引擎和第三方：只发现 URL，不作为最终事实来源。

## 2. 首页候选结构与数据就绪度

| 区域 | 状态 | 当前依据 | 上线门槛/限制 |
|---|---|---|---|
| 统一搜索 | NOT_READY | 现有首页只进入竞赛搜索；会议、高校各自有 API | 先定义聚合响应与实体分组，不用前端拼接多个静默失败请求 |
| 正在报名 | PARTIAL | 66 个竞赛届次中仅 20 个有报名或提交截止 | 只展示已核验当前届次；无日期不得推导状态 |
| 即将截止 | PARTIAL | 已有 `next_30_days`、deadline 排序和高校内部截止解析 | 卡片必须标明“官方/校内/学院截止”及来源更新时间 |
| 最近更新 | PARTIAL | 有 CompetitionUpdateEvent 与 latest 排序，但更新事件仅 1 条 | 区分“新收录”“事实更新”“来源复核”，不能按 ID 冒充更新 |
| 学术会议 | READY（基础浏览） | 206 系列、132 届次、205 系列有官网、130 届次有会期 | 可先做学科/年份/官网的最小列表，不宣称都是投稿机会 |
| 会议即将截稿 | NOT_READY | 15 个学生机会中仅 4 个有 deadline | 达到稳定覆盖前不放首页主区，不根据往年日期推算 |
| 高校认可竞赛 | PARTIAL | `school_competitions` 172 条，但认可、通知、参与证据并存 | 仅 `recognition_status` 有正式目录证据时显示“认可”；其余分别显示通知/参与 |
| 来源与更新时间 | PARTIAL | 竞赛与会议都有 source/verified/retrieved 字段 | 建立跨实体统一来源标签与过期提示后再进入所有卡片 |

## 3. 推荐的首页信息顺序

现阶段不应直接采用五大区域全部上线。按真实数据能力，建议两阶段：

### 阶段 A：当前数据可支持

1. 顶部竞赛搜索（明确标注当前只搜竞赛）。
2. 正在报名 / 作品提交中（仅核验届次）。
3. 即将截止（区分官方、学校、学院时间）。
4. 最近更新（数据不足时宁可为空）。
5. 高校证据入口（文案拆为“正式认可”“发布通知”“参与记录”）。
6. 会议库入口与近期召开会议，暂不主打截稿。

### 阶段 B：数据门槛达到后

1. 统一搜索。
2. 会议即将截稿。
3. 竞赛与会议统一时间流。
4. 按用户学校/学科关注的轻量订阅；不先做复杂进度系统。

## 4. 统一搜索目标模型

查询“计算机”时，响应应按实体分组，而不是混成一个无法解释的相关度列表：

```text
query
├─ competitions：名称 / 别名 / 标签 / 主办方 / 适合专业
├─ conferences：名称 / 简称 / 学科 / 组织方 / 推荐体系
├─ universities：校名 / 别名 / 学院
└─ evidence：高校认可目录与当前通知（作为实体关系，不是独立营销内容）
```

每个结果至少返回 `entity_type`、`id`、`title`、`matched_field`、`source_status`、`updated_at`。第一版可以继续使用 SQLAlchemy 查询，不必引入新搜索引擎。

当前竞赛 keyword 已覆盖名称、简称、主办方和标签；会议支持 keyword/discipline/organization；高校支持 keyword。缺的是聚合 API、统一排序和可解释的 matched field。

## 5. 时间节点规范

- 竞赛：报名开始、官方报名截止、学校截止、学院截止、作品提交、比赛开始/结束。
- 会议：摘要截止、论文截止、录用通知、Camera Ready、注册截止、会议开始/结束。
- 所有状态由当前届真实日期计算；典型月份、往年日期只能显示为历史参考，不能进入“正在报名/即将截止”。
- 首页卡片同时显示时间类型、来源等级和最后核验时间。

## 6. 来源卡片规范

统一呈现：

```text
来源名称 · 来源类型 · 官方/二次/第三方
原文链接
发布时间（若有）
抓取时间
最后核验时间
该来源支持的具体字段
```

高校报道类来源必须标注其证明范围。例如获奖新闻只能证明“曾参与/获奖”，不能证明当前可报名或正式认可。

## 7. 高校关系文案映射

| 数据语义 | 用户文案 | 最低证据 |
|---|---|---|
| recognition | 学校正式认可 | 学校竞赛目录、培养/评奖政策中的明确条目 |
| notification | 学校/学院发布过通知 | 官方域报名、选拔、提交或组织参赛通知 |
| participation | 学校有参与记录 | 官方获奖、结果或活动报道 |

优先级 `recognition > notification > participation` 仅用于证据强度展示，不能把低层级自动推导为高层级。

## 8. 增量落地顺序

1. 完成 V0.8.2 discovery 回归，并让关系写入严格携带 notice type/source metadata。
2. 提供统一来源展示结构和高校关系文案映射。
3. 建立最小会议列表/详情页；仅展示真实字段。
4. 新增聚合搜索 API，再替换首页搜索入口。
5. 当会议 deadline 覆盖达到产品门槛后，加入“即将截稿”。

## 9. 明确不做

- 不复制 BaoyanNews 的 HTML、CSS、品牌或商业模块。
- 不用 Mock、往年日期或人工猜测填充首页区域。
- 不优先扩建关注、进度管理、AI 推荐、付费或复杂提醒。
- 不为了首页数量放宽官方来源和会议/讲座分类规则。
