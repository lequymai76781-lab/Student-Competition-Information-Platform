# 审核吞吐与高校关系闭环设计

依据用户附件 31c35041-8a41-4e4e-90bf-444b8d7363d0。本任务涉及现有审核接口扩展，采用架构设计路径；用户明确要求持续执行、预先批准正常本地开发，不重复索取设计/实现权限。用户已同意安排一组人工计时。保留工作区此前改动，不提交或推送。

目标：复用现有 254 条候选，形成可量测、可审计的批量低风险与单条高风险审核，以及高校关系人工批准；不采集新赛事/学校，不写正式库，不迁移 schema。

## 方案

复用 ReviewQueue JSON、AdminAuditLog、现有届次关系和政策表。另造统一新关系表需要迁移；用赛事字段模拟关系会混淆语义，因此均不采用。候选主库保持只读原样，自动化/人工实验各用独立副本。

1. **风险与队列**：从当前正式值、候选、同实体同届次同字段的其他待审来源计算风险。LOW_RISK 必须身份明确、非空新增、A/B 来源且值一致；源可追溯但仍未核验时可筛为低风险，批准前必须管理员核验。覆盖/删除/冲突/无来源/弱来源/未知届次/疑似重复/名称主办方历史时间类重要字段为 HIGH_RISK，只能逐条处理。学校关系均单条。候选级高风险不可混入批量。支持 server-side 搜索、分页、排序和风险筛选；在一次请求中预载必要数据，消除逐候选/逐字段重复 SQL。
2. **低风险批量**：最多 50 条跨赛事/届次候选；显示数量、学校/赛事、字段、来源、旧值与冲突。沿用 preview token 与正式值 CAS，批量先验证全部并锁定所有目标，再执行逐条可追踪审核，整批原子提交。错误含失败候选 ID、0 成功与仍待处理清单；客户端失败保留选择/筛选/页码。
3. **时间线**：同一字段本候选及同语义外部来源按发布时间排序，缺时间置后；展示候选值、来源标题/类型/机构/原文链接、发布时间/采集时间、可达性观察和证据片段。校内截止与全国截止保持不同字段/关系，不合并成冲突。后续/延期/更正仅提示，不自动选胜者。
4. **关系闭环**：既有 collection_context.kind=school_mapping 是等价关系候选。独立服务提供详情、来源核验、准备（明确缺失届次/政策范围）及 approve/reject/defer。学校/赛事/类型不能在批准时偷偷改换；registration 不允许转 policy。通知需要明确届次，政策要求明确赛事条款及适用范围/有效期说明，未确认当前有效时只能历史表达。相同学校/赛事/届次/类型合并来源；政策不复制成每届通知。撤销/范围不一致标 RELATION_CONFLICT，要求明确人工处理，不自动覆盖。更新、来源、候选状态和审计同事务。正式关系写入纳入 reviewed_write，旧直写入口明确拒绝。
5. **计时**：独立审计事件记录 start/source_open/decision/submit/completion；不修改候选 preview revision。区分 human 与 automation，按管理员和模式汇总样本数、均值/中位/P90及理论每小时量；未完成/中断会话单列。后端时间为主，客户端阶段打点辅助，均不伪称真实阅读证据。人工样本由用户实际操作独立副本提供。
6. **验证**：先失败测试再实现。真实候选样本按实际可用类别挑选，不为达到 20/10/10/5/5 而重复伪造独立事实；不足明确报告，50 条连续低风险及 >500 分页必要时只用标识清楚的合成压力库。真实 UI/API 路径不能省来源打开/明确核验/提交。产能模型区分人工实测、自动化和假设，不能将脚本时长冒充管理员时长。

## 接口分工

- 主流程负责 field_review_service、field_reviews 路由、field_review schema、风险批量与队列集成。
- 关系服务负责新 school_relation_review_service.py 与 school_relation_review.py、关系测试；经父任务接入 field detail 的 relation 键。方法 detail(db,id)、prepare(db,id,payload,admin=)、verify_source(db,id,payload,admin=)、review(db,id,payload,admin=)。关系 payload/detail 的最终类型在实现前回传并冻结。
- 计时服务负责新 review_telemetry_service.py 与 review_telemetry.py、计时测试；方法 start(db,id,payload,admin=)、event(db,id,payload,admin=)、complete(db,id,admin_id,action)、statistics(db,admin,mode=None)。只有批准/拒绝触发完成；核验/暂缓不等同正式决定。
- 前端在契约明确后修改现有审核页/详情/API client，并新增必要的小组件和交互测试。

停止点：33 项报告与 REVIEW_THROUGHPUT 判定。R12/R13/R14 只在直接阻塞时处理；无全国扩采、正式库清理/改写或部署。
