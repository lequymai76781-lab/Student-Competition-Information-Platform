# 安全与数据一致性修复计划

本轮以《阶段开发独立审查报告》及用户指定的八类问题为边界。不新增产品功能、不迁移或清理正式数据库、不提交或推送代码。

1. 保存当前工作区差异和正式数据库 SHA256。
2. 后端权限与审核：用真实匿名/A/B/管理员身份建立失败测试；封闭通用审核队列匿名入口；将事实、队列、通知、审计纳入同一事务；故障注入及并发终态保护。
3. 届次、时间与事实可信度：覆盖2024/2025/2026跨届、实际数据库时区往返、未核验材料公开路径；显式传递届次，统一UTC时间语义和业务时区展示，隔离未核验事实。
4. 前端安全与可达性：返回地址规范化和绕过回归；身份变化立即卸载旧私人状态并丢弃晚到响应；有界分页和审核状态筛选。
5. 分页覆盖0/1/49/50/51/100以上记录；用户本人过滤、管理员完整访问及需补证状态可达。
6. 在独立临时数据库启动本地服务，用真实浏览器验证历史届次、登录返回、提交历史分页、管理员分页、跨标签切换失败与旧响应竞态。
7. 执行后端全量测试、前端回归测试、lint、typecheck、build，复查正式数据库哈希和文件差异。
8. 输出16项修复报告，明确剩余P2/P3及原48文件改动是否可批准。

正式数据库初始SHA256：`9f2eb40a640eb5bdbfc0ad4006787f7d0e910a3d1d3598b9d0d551a30768f320`。

工作分工遵循 `superpowers:dispatching-parallel-agents`：后端权限/事务、后端届次/时间/可信度、前端会话/返回地址/分页独立修改；主代理负责集成复核、隔离浏览器验证及报告。共享文件限定修改函数段，接口先同步。每组保留修复前失败与修复后通过证据，不用原有绿测代替缺陷回归。
